# U2: Flight log

Phase 3 · Effort: medium · Depends: none · Branch: `wp/U2-flight-log`

## Why

The owner (2026-11-07): "We should implement a flight log feature too so a user can see their
history." Today the game keeps only `conf/last_flight.ini` (for RESUME), written at a clean exit.
Nothing records what was flown, where, for how long, or how it ended.

## What a flight is

A flight starts when NEW FLIGHT, RESTART, RESUME or QUICK FLIGHT (U1, later) puts the aircraft in
the world, and ends at the next of these: another flight starts, the game quits, or the aircraft
crashes. Headless runs, `--frames` screenshot runs and benches never log (the same rule as
`last_flight.ini`: interactive runs only).

## Do

1. **Recorder** (`FlightRecorder`, pure, no allocation, no IO): `begin(scenario, profile id,
   wall-clock UTC)`, `update(const AircraftState&, double dtS, bool paused)` once per frame, `end(outcome)`.
   It accumulates: flight time (sim seconds, not paused), airborne time, distance (GS × dt, NM),
   maximum altitude (ft MSL), takeoffs and landings (weight-on-wheels edges; a bounce within 3 s
   is one landing), the touchdown sink rate (fpm, as AudioControl measures it), fuel at start and
   at end, and the last touchdown position.
2. **Entry** (`FlightLogEntry`): start UTC (wall clock), aircraft id, departure airport and runway,
   start type, plan name or `-`, approach or `-`, arrival airport and runway (the nearest runway to
   the last touchdown, looked up once at `end()`, within 2 NM of an airport, else `-`), flight time,
   airborne time, distance, max altitude, landings, last touchdown fpm, fuel used, and the outcome:
   `LANDED` (stopped on the ground after a landing), `ON GROUND` (never left it), `CRASHED: <reason>`,
   `IN FLIGHT` (ended airborne by a new flight or QUIT), `GAME CLOSED` (recovered, step 4).
3. **File** `conf/flightlog.csv`: a header line, then one row per flight, appended at `end()`
   (never per frame). It lives in `conf/`, so a card update keeps it. Commas in names are replaced
   by spaces. A missing or damaged file is not an error: the reader skips bad lines.
4. **Killed sessions.** Select + Start (gptokeyb) can kill the game without a clean exit
   (DEVICE.md §6). Rewrite `conf/flightlog_open.csv` (the current entry as one row, written to a
   `.tmp` and renamed) every 60 s of flight and at each touchdown; delete it when the row is
   appended. At startup, an `flightlog_open.csv` left behind is appended with outcome
   `GAME CLOSED` and deleted.
5. **Screen** FLIGHT LOG, a main-menu row after NEW FLIGHT: a summary line (flights, total hours,
   landings), then the flights newest first, one row each:
   `11-07 14:02  C172P  KPDX 28L > KOTH 04  1:12  LANDED`. A on a row opens the details (every field
   of the entry, fpm and fuel included); B goes back. Up to the 200 newest rows are read when the
   screen opens; nothing is read in flight.
6. Help: a short paragraph at the end of `assets/help/first-flight.txt` (where to find the log);
   CONTROLS.md: one line saying the screen uses the standard list keys (no new buttons).
