# R3: More region packs on releases

Phase 3 · Effort: medium · Depends: OD2 · Branch: `wp/R3-region-packs`

## Why

A new player gets the Pacific Northwest only. The datapack workflow has presets for `bayarea`,
`mthood` and `tam_diablo`, but building one means forking the repo and running Actions. Prebuilt
packs on the release page make another region a download.

## Read

- `.github/workflows/datapack.yml` and `.github/workflows/release.yml`
- `flightsim/tools/datapack/README.md` (presets, size, `ATTRIBUTION.txt`)
- `docs/DATA.md` §2 (sources and licences)
- `assets/help/data-packs.txt`

## Owns

`.github/workflows/datapack.yml`, `.github/workflows/release.yml` (a manual "attach packs" job),
`flightsim/tools/datapack/README.md`, `README.md` ("More regions"), `assets/help/data-packs.txt`.

## Do

1. A `workflow_dispatch` job that builds the presets the owner chose in OD2 and attaches each as
   `pocket-vectors-data-<preset>.zip` to a given release tag. Every zip carries its
   `ATTRIBUTION.txt`.
2. Each pack lists its bounding box and main airports in a short `REGION.txt`, which the Help page
   "data packs" mentions.
3. README "More regions": a table of the published packs with size and airports, and how to
   combine them with `make_sdcard_zip.py` (several `--data` arguments merge).

      if one doesn't exist yet)
