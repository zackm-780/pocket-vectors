# H10: Route and path overlays follow the declutter level

Phase 1.4 · Effort: medium · Depends: none · Branch: `wp/H10-overlay-auto`

## Why

The owner (2026-11-09): the route ribbon in the HUD blocks the view of the field, and the overlay
is what should separate FULL from STD declutter. Today `overlay_route` and `overlay_vpath` are
plain booleans (`settings.ini`, the settings rows, the L3 presets), drawn at every declutter
level.

## Do

1. `world::OverlayMode { Auto, On, Off }` and, in `OverlayToggles`, `routeMode` / `vpathMode`
   next to the existing bools (keep the bools: `buildWorldOverlay` reads them). A pure
   `world::resolveOverlay(const OverlayToggles& t, bool fullDeclutter)` returns the toggles with
   `route` / `vpath` set: On → shown, Off → hidden, Auto → shown only when `fullDeclutter`.
2. Settings: `overlay_route` and `overlay_vpath` take `auto | on | off`, default `auto`. Old
   files: `true` reads as `on`, `false` as `auto` (`false` was everyone's default, and the owner
   wants the new default for them), anything else as `auto`. Written back as the words.
   `overlay_airports` / `overlay_runways` stay booleans.
3. Settings rows OVERLAY ROUTE and OVERLAY PATH cycle AUTO → ON → OFF.
4. Presets (L3 and the pause-menu OVERLAYS row): AUTO (route and path auto, airports and
   runways off) → ROUTE+PATH (both on) → AIRPORTS (route and path auto, airports and runways
   on) → ALL (all on) → OFF (all off) → AUTO. A mix that matches none is CUSTOM and goes to AUTO
   next. The HUD message stays `OVERLAYS <name>`.
5. `App.cpp`: resolve with `hudOptions.declutter == Declutter::Full` every frame before the
   `layersOn` test, so STD and MIN draw no route or path in auto, and a declutter press takes
   effect on the next frame. The chase view uses the same rule.
6. Help: in `assets/help/flight-plan.txt`, a short paragraph: the route and path overlays show
   only at FULL HUD (Y) unless set ON in SETTINGS; L3 cycles the presets. `docs/HUD.md` §8: the
   new modes, the defaults and the preset order.
