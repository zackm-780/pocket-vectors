# N11b: Plan edits on the screens: Direct-To, new destination, prompts, messages and undo

Phase 1.4 · Effort: high · Depends: N11a · Branch: `wp/N11b-plan-edit-ui`

## Why

N11a writes the rules (`src/nav/PlanEdit.h`, `docs/NAVIGATION.md` §2.4). This card routes every
plan change the pilot can make through them, adds the missing ones (new destination in flight,
delete / activate a leg, Direct-To next), the KEEP ROUTE / CLEAR ROUTE prompt, one short HUD
message per change, and a one-press undo for about 10 s (owner, 2026-11-09).

## Do

1. **One path for every edit:** each screen builds a `PlanEditResult` with N11a's functions;
   if `destructive`, call `Navigator::stashUndo(undoLabel, simTime)` first; then
   `Navigator::setPlan(result.plan)` and post `result.message` (the HUD message line, which the
   map page also shows). Nothing calls `clearPlan` in flight any more.
2. **FLIGHT PLAN (in flight)** rows: `DIRECT TO IDENT...`, `NEW DESTINATION...`,
   `CHANGE APPROACH...`, `ARRIVAL (STAR)...`, `DEPARTURE (SID)...` (on the ground only, with a
   `DEPARTURE RUNWAY...` row next to it), `ACTIVATE APPROACH` (today's RE-ENTER APPROACH), and
   `UNDO <LABEL>` while an undo is available. Leg rows: A = Direct-To (rule 1), X = ACTIVATE LEG,
   Y = DELETE (rule 7); the footer says so.
3. **Direct-To (search screen):** the hit goes through `PlanEdit::directTo` (rules 1–4). After a
   Direct-To another airport (rule 4) push the approach screen for it, with a `NOT NOW` row at
   the top (owner: "offer the new airport's approaches next").
4. **New destination:** the airport search, then its runway (optional), then one prompt `KEEP
   ROUTE` / `CLEAR ROUTE` with CLEAR selected (a two-row confirm screen, B = cancel). Rule 5.
   Then offer the approaches as in step 3.
5. **Setup screens:** changing the origin runway no longer clears a quick plan
   (`FlightSetup.cpp`, "the origin runway is part of the plan"): it goes through
   `changeDepartureRunway` (rule 6), re-assembling the SID for the new runway when it serves it.
   Changing the destination on the setup FLIGHT PLAN screen with a plan loaded uses rule 5 and
   the same prompt.
6. **One press:** L1 + Select (`DirectTo`) becomes DIRECT TO NEXT (rule 8); with no plan it still
   opens the Direct-To search. The map page's A on a waypoint uses rule 1.
7. **Undo:** `Action::PlanUndo`, R1 + Start and Ctrl+Z. While an undo is available the
   destructive edit's message reads `ROUTE REPLACED  R1+START UNDO` (fit the message line); the
   press restores the plan (`ROUTE REPLACED UNDONE`). Outside the window: `NOTHING TO UNDO`.
8. **Help and docs:** `assets/help/flight-plan.txt` gets the Direct-To rules in four short lines
   (in plan, off plan then rejoin, destination, other airport), the new destination prompt, the
   leg buttons and the undo; `docs/CONTROLS.md` the R1 + Start row.
